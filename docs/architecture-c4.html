PDF Exchange English のソフトウェアアーキテクチャ

英文PDF・テキストから文を取り出し、Claude で日本語訳を付けて学習カード・シャドーイング用テキスト・音声にする Next.js アプリの構成を、C4モデルの4段階で示します。図はすべてソースコード（src/、db/migrations/、scripts/）から読み取ったものです。

Level 1システムコンテキスト図

誰がこのシステムを使い、どの外部サービスに頼っているかを示します。翻訳と音声は有料APIのため、システム側で1日の利用量を制限しています。

Level 2コンテナ図

システムの中を、別々に動く単位に分けたものです。ブラウザ上の画面と Vercel 上のサーバーは同じ Next.js プロジェクトですが、実行場所が違うため別のコンテナとして扱います。DB には権限を絞った app_user ロールで接続し、所有者ロールはマイグレーションだけで使います。

Level 3コンポーネント図：アプリサーバー

上段が入口（Route Handler と Server Component）、中段が src/lib/ の処理、下段が接続部品です。auth.ts のセッション確認は、ほぼすべての入口から呼ばれるため矢印を省いています。

コンポーネント図：Webアプリ（ブラウザ）

画面は Client Component の組み合わせです。共通の状態は UsageProvider（今日の残り文字数）と Better Auth の useSession の2つで、翻訳結果はリロード対策として sessionStorage に保存します。

翻訳チケット（Issue #54）

サーバー側のみ実装済み

最初に本文を受け取ったときに、ログイン中なら翻訳1件ぶんのチケットを発行します。チケットがあれば、翻訳中にセッション（2時間）が切れても、発行時のユーザーとして翻訳・保存できます。/api/extract と /api/process の withTicket、x-translation-ticket ヘッダーは用意済みですが、page.tsx からはまだ送っていません。

使用量の予約

Claude を呼ぶ前に usage テーブルへ INSERT … ON CONFLICT DO UPDATE … WHERE で予約し、個人の枠と全体の枠の両方を同時に確認します。ロック待ちが USAGE_LOCK_TIMEOUT_MS を超えたら 429（reason: busy）で断ります。

補足デプロイと品質管理

実行環境

Vercel（Node 24）。画面とAPIは同じ Next.js 16 アプリで、API と Server Component は Vercel Functions で動きます。環境変数を変えたら Redeploy が必要です。

データベース

Neon（サーバーレス Postgres）。@neondatabase/serverless の Pool を、認証用（auth.ts）とアプリ用（db.ts）で1つずつ持ちます。どちらも DATABASE_URL_APP を使います。

CI

GitHub Actions が PR ごとに 型チェック → lint → テスト（単体・API・UI）→ ビルド → npm audit --omit=dev を順に実行します。DB 統合テストはローカルだけで動かします。

テスト

Vitest 5 と Testing Library。src/__tests__/ の下を unit / api / ui / integration に分けています。
