# 設計メモ(コードから外したコメントの「理由」)

コードのコメントを「ファイルの役割」と「関数の引数・返り値」だけに絞ったとき、関数の中にあった「なぜそうしたか」の説明を、ここに移した。コードを直すときは、先にここを読んで、理由を壊さないようにする。

- 書いてあるのは、コードを読んだだけでは分からない理由(設計上の判断、避けた罠、制約)。
- 理由が変わったときや、その部分のコードを消したときは、この文書も直す。
- 関数名は、そのファイルの中の関数・定数の名前。
- 作成日: 2026-11-06

## アプリの画面と API(src/app、src/types)

### src/app/page.tsx
- **保存済みの結果の復元(useEffect)**
  - sessionStorage からの復元は、`useState` の初期化時ではなく、マウント後の effect で行う。初回のクライアント描画を、サーバーが描いた空の状態と一致させて、ハイドレーションの不一致を避けるため。
  - JSON が壊れている、ストレージが使えない(Safari のプライベートモード、容量超過、無効化)ときは、初回訪問と同じ扱いで、空の状態から始める。
- **保存の同期(useEffect)**
  - 新しい実行の冒頭で `setSentences([])` を呼ぶのも、通常の state 変更なので、古い保存エントリも同じ effect で消える。
  - 保存は努力目標。容量超過やプライベートモードのエラーは無視する。
- **processText 全体**
  - ファイルのアップロードと貼り付けは、どちらも英文の文字列にしてから、チャンクに分けて1つずつ順に翻訳する。全体の完了を待たず、結果が届くたびに、例文の一覧と進捗を更新するため(issue #10)。
  - チャンクは**意図的に並列にしない**。並列化は別の将来の改善で、今回のスコープ外(`api-pivot-long-form.prd.md` の Phase 3)。
- **使用量の事前チェック**
  - 翻訳を始める前に、今日の残りを超えないか確認して警告する。途中で上限に当たって、中途半端な結果になるのを避けるため。
  - これは表示のための事前チェック。実際の判定は、翻訳 API(サーバー側)が行う。使用量を取得できなければ、このチェックは省く。
  - サーバーは短いチャンクにも最低課金(`minCharge`)をかけるので、ここでも同じ数え方をする。
- **`collectedSentences`(保存用の配列)**: `setSentences(prev => ...)` は state を更新するだけで、ループが終わった時点の最終リストを同期的には読めない(古いクロージャの問題)。そのため、保存用に同じ内容を、普通の配列にも並行して集める。
- **429 以外の失敗(`failedChunks`、`consecutiveFailures`)**
  - サーバーの不具合や DB 障害などで失敗したチャンクは、飛ばして続ける。ただし、抜けのある結果を「完了」として保存しないよう、失敗した数を数える。
  - 連続して失敗するときは、残りも同じ理由で失敗する可能性が高いので、叩き続けずに中断する(連続失敗の上限は `MAX_CONSECUTIVE_FAILURES`、3 回)。
  - チャンクの失敗時は、リトライせず、ログに出して続行する。
- **429(上限に到達)**: 残りのチャンクも同じく断られるので、続けずに中断する。
- **中断・一部失敗のときの保存**
  - 上限に達して中断したときは、案内を出して終わる。翻訳できた分は画面に残すが、**一部しか翻訳されていない結果を「完了」として履歴に保存しない**。
  - 一部のチャンクが失敗したときも、翻訳できた分は表示するが、抜けのある結果は履歴に保存しない。
- **履歴への自動保存**: ログイン中だけ保存する。保存はベストエフォートで、保存に失敗しても翻訳エラーにはしない(結果は、どちらの場合も画面に表示済みのため)。
- **handleTextSubmit**: 貼り付けはファイルではないので、`/api/extract` を経由せず、貼り付けたテキストをそのまま渡す。

### src/app/api/process/route.ts(POST)
- **`action` の構成**: クライアントが、まずチャンクの一覧を取得し(`split`)、次に1チャンクずつ翻訳して(`translate`)、結果が届くたびに画面を更新する。長文で1つのスピナーだけにならず、進み具合が見えるようにするため(issue #10)。
- **一括処理の廃止**: 以前の一括処理(`action` なし)は廃止した。1リクエストの中で全チャンクを Claude に通すため、リクエスト単位の使用量制限では計測できなかった。
- **大きすぎるチャンクの拒否**: 使用量テーブルや Claude に触れる前に断る。1回のリクエストで、1日の文字数の上限を回避されないようにするため。
- **使用量の予約**: Claude を呼ぶ**前**に予約する。チェックは、お金が使われる場所で行う必要があり、クライアント側の別の呼び出しではいけない。
- **最低課金(`amount`)**: 短いチャンクでも、Claude の呼び出しには固定のコストがかかる。そのため、最低課金の分を予約する。
- **busy の 429**: busy は、上限を超えたのではなく、DB が混み合って予約できなかっただけ。リセット時刻は無関係なので返さず、`Retry-After` を 5 秒にして、数秒後の再試行を促す。
- **レスポンスの `sentences` に `id` を付けない**: クライアントが、チャンクごとの結果を追加するときに ID を振る。1チャンクが何文になっても、チャンクをまたいで連番が途切れない。
- **返金(`refundUsage`)の条件**
  - Claude を呼べずに失敗したときだけ、予約した分を返す(何も消費していないため)。
  - 応答を受け取ったあとの失敗(`ClaudeResponseError`)は、課金済みなので返さない。返すと、出力が途中で切れる入力を送り続けて、枠を減らさずに費用だけ発生させられてしまう。

### src/app/api/tts/route.ts(POST)
- **許可リストによる制限**: 音声合成は ElevenLabs の費用がかかるうえ、利用回数の制限をまだ持たない。そのため、試験導入として、許可リストのアカウントだけに限っている(`FEATURE_ALLOWED_EMAILS`)。画面でボタンを隠すだけでは、curl などで直接叩けるので、判定は外部 API を呼ぶ直前のここで行う。公開するときは、この判定の条件を変えるだけで済む。
- **文字数の上限(`MAX_TTS_CHARS`)**: 許可されたアカウントでも、暴走や誤操作で巨大な本文が送られると高額になるため、上限を設けている。

### src/app/api/usage/route.ts(GET)
- **`dynamic = "force-dynamic"`**: リクエストごとにセッションと使用量を読むので、ビルド時に静的に評価させない。
- **API の位置づけ**: 画面に「今日の残り」を出し、音声などの機能を出し分けるための、読み取り専用の API。使用量の予約はしない。ここで「使える」と返しても、実際の判定は、各 API ルートが外部 API を呼ぶ直前に行う(この値を信用して、判定を省かない)。許可リストのメールアドレスそのものは返さず、「使えるかどうか」だけを返す。

### src/types/index.ts
- **`ProcessingState` の `completedChunks` / `totalChunks`**: 長文をチャンクごとに翻訳する間、静的なメッセージではなく「Translating... (3/12 chunks)」のように、進み具合を表示するための項目(issue #10)。
- **`UsageInfo`**: `GET /api/usage` の応答。画面に残量を表示し、機能(音声)を出し分けるために使う。表示のためだけの値で、制限の判定は、サーバー側(各 API ルート)で別に行う。各項目の意味は次のとおり。
  - `remaining`: 今日あと何文字まで翻訳できるか。個人の枠と全体の枠のうち、小さいほう。
  - `limit`: 個人の1日の上限。
  - `minCharge`: 1リクエストの最低課金(文字数換算)。短いチャンクでも、この分は減る。
  - `constrainedBy`: 残りを決めているのが、個人の枠か、全体の枠か。
  - `resetAt`: 次のリセット時刻(ISO 8601、UTC)。

## 部品(src/components)

- **ClickableEnglishText**: `SentenceCard`(カード表示)と `ShadowingSheet`(シャドーイング用テキスト)の両方で、単語の検索を使えるよう、共用の部品にした。英文は空白で分割し、各単語をクリックすると、Oxford Learner's Dictionaries で引ける。
- **DownloadPdfButton**
  - PDF は、html2canvas で DOM を画像にして、jsPDF でページにまとめる。翻訳には英語と日本語が混在するので、テキストベースの PDF 生成だと、日本語フォントの埋め込みが問題になる。画像にすれば、それを避けられる。
  - `handleDownload`: 縦長の画像を、ページごとのスライスに切り、余白の内側に1枚ずつ置く。「ずらして繰り返し貼る」方式を採らない理由は、`src/lib/pdf-layout.ts` の `computePdfLayout` の項を参照。
- **DeleteDocumentButton(`handleDelete`)**: 削除 API が失敗したり、通信エラーになったりしたら、下の `setIsDeleting(false)` に流して、ボタンを再び押せるようにする。
- **ShadowingSheet**: 日本語訳なしの、英文だけのスクリプトにする。短い文は1行にまとめて(`buildShadowingLines`)、1文1行ではなく、自然な台本として読めるようにする。
- **SentenceResultView**: 画面の見た目は、`page.tsx` のカード一覧とシャドーイングの切り替えと同じ。ただし、`page.tsx` は表示の切り替えを sessionStorage にも保存していて、state の持ち方が違う。そのため、`page.tsx` は変更せず、こちらは履歴の詳細ページ専用として、自己完結させた。
- **SentenceCard**: 音声の生成は試験導入で、許可されたアカウントだけが使える(判定は、サーバー側でも行う)。取得済みの音声(`audioUrl`)があれば API を呼ばないので、誰でも再生できる。
- **UsageNotice**: 残りが最低課金(`minCharge`)に満たないと、実際には1回も翻訳できない。そのため、0 でなくても「使い切り」として扱う。
- **UsageProvider**
  - 全体: 「今日の残り」と、音声などの機能の利用可否を、アプリ全体で1回だけ取得して共有する。文のカードが何百枚もあるので、カードごとに API を呼ばないため。ここで持つのは表示用の値で、制限の判定は、サーバー側(各 API ルート)が別に行う。
  - `fetchUsage`: 取得に失敗してもエラーにはせず、`null` を返す。表示を出さないだけにして、翻訳自体は止めない。
  - `useEffect`: ログイン・ログアウトで、使える機能や上限が変わるので、取り直す。古い値を見せないよう、いったん `null` にする。セッションの確認中(`isPending`)は取得しない。
  - `refresh`: 一時的な取得の失敗で、表示を消したり、音声ボタンを無効にしたりしないよう、失敗したときは前回の値を残す。
- **AuthButton の `eslint-disable`(`no-img-element`)**: 外部ドメインの画像で、`next/image` の設定を避けるため。※元のコードには理由が書かれていなかったので、これは整理した担当者の推測。実際の理由と違えば、直す。

## 共通のロジック(src/lib)

### access.ts
- **`isFeatureAllowed`**: メールアドレスが未確認のアカウントは許可しない。他人のアドレスで登録される恐れに備えるため。Google ログインのメールアドレスは、確認済みとして返る。
- **全体**: 公開するときは、判定の条件を変えるだけで済み、ブランチの操作は要らない。`FEATURE_ALLOWED_EMAILS` が未設定か空のときは、誰にも許可しない(安全側)。

### auth.ts
- **`modelName` の設定**: `documents` / `sentences` の `user_id`(text 型)が参照する名前を、`users` / `sessions` / `accounts` / `verifications` という複数形にそろえている。Postgres では、`user` と `session` が SQL の予約語のため。
- **セッションは、ログインから2時間で必ず切れる(延長しない)**: 盗まれたクッキーを長く使われないようにするため(Issue #50)。
  - 「最後の操作から2時間」にしない理由: 盗んだ人がアクセスし続けると、そのたびに期限が延びて、ずっと使えてしまう。`disableSessionRefresh: true` で延長を止めている。
  - 1時間ではなく2時間にした理由: 翻訳の途中で切れて、履歴に保存できなくなる場面を減らすため。

### auth-client.ts
- **`baseURL` を省略している理由**: 同一オリジンの `/api/auth` へ、相対パスでリクエストさせるため。

### client-ip.ts
- **`expandIpv6` / `normalizeIp`**: IPv6 は、端末ごとにアドレスが変わる(プライバシー拡張)ので、1つの回線が、ほぼ無限にアドレスを持てる。通常は、1回線に /64 が割り当てられるので、前半の4グループを、1つの主体としてまとめる。まとめないと、IP ごとの上限を簡単に回避できてしまう。
- **`normalizeIp`**: 判別できないものは `"unknown"` にまとめる。`unknown` は、1つの共有の枠になる(安全側)。IPv4-mapped IPv6(`::ffff:1.2.3.4`)は、IPv4 として扱う。
- **`getClientIp`**: Vercel では、`x-forwarded-for` がクライアントの公開 IP で、外部から付けられた値は上書きされる(偽装の防止)。`x-vercel-forwarded-for` は同じ値で、手前にプロキシを置いても上書きされないため、先に見る。

### db.ts
- **`getPool`**: `documents` / `sentences` 専用の Pool で、`src/lib/auth.ts` の Pool とは別のインスタンス。DB は同じ Neon のプロジェクトだが、責務を分けて、疎結合を保つため。

### documents.ts
- **`saveDocument`**: `documents` の1行と `sentences` の N 行を、1つのトランザクションで保存する。RLS は、そのトランザクションの中で `set_config('app.user_id', ...)` を設定して効かせる(`chunk-persistence.prd.md` の保存方式どおり)。

### format.ts
- **`jstFormatter`**: DB には UTC(`timestamptz`)のまま保存し、表示するときにだけ、ローカルのタイムゾーンへ変換する。独自のオフセット計算はせず、ネイティブの `Intl.DateTimeFormat` を使う。
- **`overLimitMessage`**: 表示のための事前チェック。実際の判定は、翻訳 API がサーバー側で行う。

### pdf-layout.ts
- **`PDF_MARGIN_PT`**: 40pt は約 14mm。A4(595×842pt)の上下左右に取る。
- **`computePdfLayout`**: 以前は、画像をページ全体に貼り、位置をずらして次のページにも貼り直していた。その方式では余白が取れず、余白に隣のページの内容がはみ出して見える。そのため、ページごとに画像を切り出して貼る。
- **`slicePx`**: 1ページに入る画像の高さ(px)は、小数を切り捨てる。はみ出さないようにするため。

### sentence-toc.ts
- **`buildTocGroups`**: カードが 100 件を超えると、10 件ずつの区間ジャンプの目次("1-10"、"11-20")を出す。100 件以上のカードをスクロールして探すのは遅いため。100 件以下では目次を出さず、通常のケースでは非表示のままにする。

### shadowing-sheet.ts
- **`buildShadowingLines`**: 文末の句読点ごとに改行すると、"Are you sure?" のような、短い行ばかりになって読みにくい。そのため、次の文を足すと 80 文字を超えるまで、文を1行に詰め、超えたら新しい行にする。

### usage-limits.ts
- **全体(既定値)**: 環境変数で上書きでき、未設定や不正な値のときは、既定値を使う(設定を忘れても、安全な値で動く)。環境変数はサーバー専用で、`NEXT_PUBLIC_` は付けない。変更は、Vercel で保存したあと Redeploy しないと反映されない。
- **既定値の根拠**: 「自分以外のユーザー全員の利用総額を、月 5,000 円に収める」前提。1,000 文字あたり約 1.1 円で計算すると、31 日分で約 14 万文字/日になるが、出力が想定より長くなる最悪のケース(実費が最大で約 1.55 円/1,000 文字)でも収まるよう、10 万文字/日にしている。実際の単価は、翻訳 API のレスポンスの `usage` を見て見直す。
- **`UsageLimits` の各上限の意味**
  - `anonIpChars`: 未ログインの、同じ IP が1日に使える上限。
  - `anonTotalChars`: 未ログイン全員の合計の上限。個人の回避ができても、費用の天井になる。
  - `userChars`: ログイン済み(自分以外)の、1ユーザーの1日の上限。
  - `othersTotalChars`: 自分以外の全員(未ログイン + ログイン済み)の合計の上限。
  - `ownerChars`: 自分(許可リストのアカウント)用で、誤操作や暴走に備えた安全装置。
  - `maxTranslateChunkChars`: 翻訳1リクエストで受け付ける、チャンクの最大文字数(通常の分割は 1,500 文字)。
  - `lockTimeoutMs`: 他のリクエストが持つ行のロックを待つ最大時間。詰まったときに、いつまでも待たせず、数秒で諦めて断る(使い放題にならない側に倒す)。
  - `minChargeChars`: 翻訳1リクエストの最低課金。Claude の呼び出しには、プロンプトとツール定義の入力トークンが毎回かかる。短いチャンクを大量に送られて、費用が膨らむのを防ぐため、短くても、この文字数分は予約する。
- **`readLimit`**: DB の `int`(32bit)に入らない値だと、予約の SQL がすべてのリクエストで失敗する。そのため、`INT32_MAX` 以下に制限している。

### llm.ts
- **`ClaudeResponseError`**: Claude が応答したあとの失敗(解析できない、出力が途中で切れた)を表す。この時点でトークンは消費済みなので、呼び出し側は、予約した分を返してはいけない。API の呼び出し自体の失敗は、普通の `Error` のまま(未課金)。
- **`maxTokensFor`**: 出力トークンの上限を、チャンクの長さに合わせる。固定(8192)だと、短いチャンクに「長文を書いて」と埋め込まれたとき、1回で大量の出力を課金される。出力には、ツール呼び出しの JSON(原文 + 訳)が入り、実測では、チャンクの文字数の約 1.2 倍のトークンになる。その約 1.7 倍(2.0 倍 + 256)を上限にして、通常は切れず、暴走したときの出力課金(入力の 5 倍の単価)が、予約の見積もりを大きく超えないようにする。
- **`translateTool`**: 新しい Structured Outputs API ではなく、Tool Use を使う。Structured Outputs は、現時点で Sonnet 4.5 / Opus 4.1 のみ対応で、`CLAUDE_MODEL` の Haiku 4.5 が対象外のため。
- **`splitLongPart`**: 句読点のない長い文章(PDF から抽出した箇条書きなど)は、1つの「文」が `maxChars` を超える。そのままだと、サーバーが受け付ける最大文字数を超えて、翻訳が失敗する。そのため、空白の位置で(空白もなければ `maxChars` で強制的に)分ける。
- **`processChunk`(前半の `catch`)**: 接続の失敗やタイムアウトは、応答が返らなかっただけで、サーバー側では、生成と課金が進んでいるかもしれない。未課金と言い切れないので、`ClaudeResponseError` にして、返却させない(安全側)。Claude が拒否した失敗(4xx/5xx、レート制限、過負荷)は、未課金なので、そのまま投げて、返却させる。
- **`processChunk`(後半の `try`)**: 応答を受け取ったあとは、課金済みなので、どんな失敗も `ClaudeResponseError` にして、返却させない。
- **`parseResponse`**: 費用の見積もり(1,000 文字あたりのトークン数と単価)を、実測で見直すためのログ。本文は出さず、文字数とトークン数だけを残す。

### usage.ts
- **全体**: 外部の有料 API を呼ぶ**前**に、使用量を予約し、上限を超えるなら断る。使用量は、Neon の `usage` テーブルに置く(サーバーレスは、メモリを共有しないため)。
- **`UsageSubject`**: `owner` は、許可リストのアカウント(自分)で、全体の予算には数えず、別枠の安全装置だけを適用する。`user` は、ログイン済みの自分以外。`anon` は、未ログイン。
- **`hashIp`**: 生の IP アドレスは保存せず、鍵つきのハッシュにする。DB が漏れても、元の IP を復元できないようにするため。鍵は、既存の `BETTER_AUTH_SECRET` を流用する(新しいシークレットを増やさないため)。
- **`bucketsFor`**: 1回の予約で、個人の枠と全体の枠をまとめて確認する。キーは次のとおり。
  - `u:<id>`: ログイン済みの個人。
  - `ip:<hash>`: 未ログインの IP。
  - `anon:*`: 未ログイン全体。
  - `others:*`: 自分以外の全員の合計(予算の天井)。
- **`reasonFor`**: 個人の枠を超えたか(`personal`)、全体の枠を超えたか(`pool`)で、画面に出す案内を変える。
- **`RESERVE_SQL`**: `INSERT ... SELECT ... WHERE` にしているのは、`ON CONFLICT ... WHERE` が更新側にしか効かず、新しいキーの1回目が上限を超えても通ってしまうため(本番 DB でのドライランで確認済み)。条件を満たさないときは、0 行が返る。日付は UTC で、トランザクションの中の `now()` は一定なので、同じ予約のすべての枠で、同じ日になる。
- **`ReserveResult` の `busy`**: 他のリクエストのロックを待ち切れなかった(または、デッドロックとして取り消された)場合。上限を超えたわけではないので、少し待って、もう一度試せばよい。
- **`isBusyError`**: Postgres のエラーコード `55P03` は、ロックの待ち時間切れ。`40P01` は、デッドロックによる取り消し。
- **`beginWithLockTimeout`**: `SET LOCAL` はパラメータ(`$1`)を取れないので、検証済みの整数を、そのまま埋め込む。`BEGIN` と同じ1回の通信で送るので、往復は増えず、そのトランザクションの中だけで有効。
- **`reserveUsage`**
  - すべての枠を、1つのトランザクションで予約する。どれか1つでも上限を超えたら、全体をロールバックし、片方だけ消費されることがない。
  - 同時のリクエストがお互いを待ち合って、デッドロックしないよう、キーの順に処理する。
  - ロックの待ち時間切れやデッドロックは、予約できなかっただけなので、例外にせず、`busy` として返す。
  - `ROLLBACK` 自体が失敗した(接続がすでに切れている)場合は、無視して、元のエラーを優先する。
- **`refundUsage`**
  - 予約した日(UTC)の行に対して戻すので、日付をまたいでも、別の日の使用量を減らさない。
  - 返却の失敗は、元のエラーの処理を邪魔しないよう、ログに残すだけにする(戻せなかった分は、その日の枠が少し余計に減るだけ)。接続の取得も例外処理の中に入れるのは、DB に繋がらないときも、元の処理を邪魔しないため。
- **`getRemainingUsage`**: 予約はしない。画面に表示するためだけの値で、実際の判定は、`reserveUsage` がサーバー側で行う。個人の枠と全体の枠のうち、残りが最も小さいものを返す。`limit` に使う先頭の枠(`personalBucket`)は、常に個人の枠。
- **`nextResetAtIso`**: 使用量は、UTC の日付ごとに数えるので、次の UTC 0 時(日本時間の 9 時)にリセットされる。API 間のやりとりは、ISO 8601 で返す(日付・時刻の規約)。
- **`limitMessage`**: UI では、時刻のタイムゾーンを必ず明示する。

## テスト(src/__tests__)

### integration/db-env.ts(本番 DB を守る安全策)
- **全体**: DB 統合テストの接続先を決める補助モジュールで、本番 DB を壊さないための安全装置を兼ねる。
  - `DATABASE_URL_TEST_OWNER`(テスト用ブランチの所有者ロール)が未設定なら、統合テストは飛ばす。
  - テスト用の接続先が、本番の接続先(`DATABASE_URL`、`DATABASE_URL_UNPOOLED`、`DATABASE_URL_APP`)と同じなら、例外を投げて中止する。
- **アプリ用(`app_user`)の接続先**: 本番の `DATABASE_URL_APP` の資格情報に、テスト用ブランチのホスト名を組み合わせて作る。Neon のブランチは、本番のロールとパスワードを引き継ぐため。この作り方なら、`.env.local` を書き換えずに済む。
- **`endpointId`**: Neon の接続先は `ep-xxxx(-pooler).region.aws.neon.tech` の形。先頭がブランチごとのエンドポイント ID なので、これを比べて、「本番と同じ接続先か」を判定する。pooler 版と直接版が、同じブランチを指すため、`-pooler` は除く。

### integration/usage-db.test.ts
- **全体**: 本物の Postgres(Neon のテスト用ブランチ)を使う。同時に大量のリクエストが来ても、上限を超えないこと、半端な状態が残らないことが主眼。`DATABASE_URL_TEST_OWNER` が未設定なら、このファイルのテストは飛ばされる。
- **`amount`(補助関数)**: 所有者ロールで、テーブルの中身を直接読む。アプリの経路を通さずに確かめるため。
- **`beforeAll`**: アプリの接続先(`DATABASE_URL_APP`)を、テスト用ブランチ(`app_user`)に差し替えてから、`@/lib/usage` と `@/lib/db` を読み込む。差し替えの前に読み込むと、本番の接続先を掴むため。`afterAll` で元に戻す。
- **「【回帰】新しい主体の最初の予約が上限を超えるなら、拒否する」**: `ON CONFLICT ... WHERE` だけの書き方では、新規行の初回が、上限を素通りした。その回帰を防ぐテスト。
- **「【複数の枠】途中の枠で失敗したら…」**: 未ログインの枠は、キーの順に `anon:*` → `ip:…` → `others:*` と処理する。最後の `others:*` で失敗したとき、先の2つの加算が残らないことを確かめる。
- **「デッドロックなし・整合」(200 リクエスト)**: 未ログインとログイン済みを交互に混ぜて、キーを取る順番が食い違う状況を作る。確かめる点は4つ。
  1. デッドロック(Postgres の `40P01`)などの例外が、1件も出ないこと。
  2. 全体の枠が、ちょうど 5,000 で止まること(200 件中、成功は 50 件)。
  3. 先に加算してから取り消された分が、残っていないこと(`anon:*` の合計 = 成功した未ログインの数 × 100)。
  4. `ip:%` の合計も、同じ値になること。
- **「予約と返却が同時に起きても…」**: 先に 20 件(2,000 文字)を予約しておき、その 20 件の返却と、新しい 20 件の予約を同時に流す。最終値は、2000 − 2000 + 2000 = 2000 になる。
- **「ロックの待ち時間」**
  - `seedAndLockPool` は、別の接続で全体の枠の行をロックしたままにして、他のリクエストが詰まる状況を作る。
  - `Promise.race` の `sleep(8000)` は、待ち時間の上限が効かないと固まることを検出するための番兵。
  - 経過時間が、900ms 以上(設定した時間は待った)、かつ 6000ms 未満(いつまでも待たない)であることを確かめる。
  - 「何も消費していない」「個人の行も作られていない」は、`busy` のときに副作用が残らないことの確認。
  - 返却がロックで詰まった場合は、例外にせず、諦める。返却できなかったので、量はそのまま。
  - 待ち時間(`lock_timeout`)の設定は、そのトランザクションの中だけに限る。使い回される接続に残らないよう、`show lock_timeout` が既定の `"0"`(無制限)であることを確かめる。
- **「DB に接続できないとき」**: 予約は例外にして、使い放題にならないようにする。返却の失敗は、元の処理を邪魔しないよう、ログだけ残す。
