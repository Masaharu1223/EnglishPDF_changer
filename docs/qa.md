## Q1. アップロードしてから、最初のチャンクが Claude に届くまで、どう流れるか

**A.** 今のコードでは、Claude に届くまでに、ブラウザとサーバーの往復が4回ある。

PDF / TXT の場合の流れ:

1. **ブラウザ**: ファイルをメモリに読み込み、base64 の文字列に変える(サイズは約1.3倍になる)。
2. **ブラウザ → サーバー**: `/api/extract` に、ファイル全体を JSON で送る。これがアップロード。
3. **Vercel**: 本文を最後まで受け取ってから、関数を起動する。
4. **サーバー**: JSON を読み、PDF / TXT から本文のテキストを取り出して返す。
5. **ブラウザ → サーバー**: `/api/process`(`action: "split"`)にテキストを送り直し、チャンクに分けてもらう。
6. **ブラウザ → サーバー**: `/api/usage` で、残りの使用量を確かめる。
7. **ブラウザ → サーバー**: チャンク1を `/api/process`(`action: "translate"`)に送る。サーバーは使用量を引いてから、**ここで初めて Claude に送る**。

貼り付けたテキストの場合は、1〜4 がなく、5 から始まる。

8 以降は、ブラウザがチャンクを1つずつ送り、1つ返ってくるたびに次を送る(ループはブラウザ側にある)。

関係するコード:
- `src/app/page.tsx` の `handleFileSelected`(1, 2)と `processText`(5〜7 とループ)
- `src/app/api/extract/route.ts`(4)
- `src/app/api/process/route.ts`(5, 7)

## Q2. アップロードの途中で通信が切れたら、どうなるか

**A.** サーバー側では何も起きない。ブラウザにはエラーが表示され、もう一度アップロードすればやり直せる。

- **サーバー**: Vercel は本文を最後まで受け取るまで関数を起動しない。そのため、次のどれも行われない。
  - ログインの確認
  - テキストの抽出
  - 使用量を引くこと(課金されない)
  - DB への書き込み
- **ブラウザ**: `fetch` が通信エラーで失敗し、`handleFileSelected` の `catch` でエラーを表示する。
  - 表示されるのはブラウザの生のメッセージ(Safari なら「Load failed」など)で、分かりにくい。
- 中途半端な状態は残らない。

## Q3. ログイン(セッション)の確認は、アップロードの前か後か

**A.** 後。アップロードが終わってから確認する。

- ブラウザは、Cookie(セッション)をリクエストの最初に送っている。けれども、Vercel はファイルを全部受け取るまで関数を起動しないので、サーバーが確認できるのは受け取り終わった時点になる。
- そのため、アップロード中にちょうどセッションの期限(2時間)が来ると、未ログインとして扱われる。
  - チケット(#54)も出ないし、履歴にも保存されない。
- ブラウザ側で Cookie の期限が先に切れていると、Cookie 自体が送られない。この場合も、未ログインとして扱われる。

アップロードの前に確認する方法は、Issue #57 で検討する。前に確認しても、その結果をあとのアップロードに引き継ぐには、何か証拠を渡す必要がある。つまり、チケットと同じものが要る。

## 関連する制約

- Vercel の関数が受け取れる本文には、上限がある(約4.5MB)。ファイルは base64 にすると約1.3倍になるので、**約3.4MB を超える PDF は、今のコードではアップロードできない**と考えられる(未検証)。
