1. C4モデルの読み方

C4モデルは、システムの全体像を「地図のズーム」のように 4 段階で描く方法です。広い範囲から始めて、少しずつ拡大します。

  1. レベル1 システムコンテキスト: このシステムを 1 つの箱として、周りの人や外部サービスとの関係を描く。
  2. レベル2 コンテナ: システムの中を、動くもの(ブラウザ上のUI、サーバー、DB など)に分けて描く。「コンテナ」は Docker のことではなく、「独立して動く部品」の意味。
  3. レベル3 コンポーネント: 1 つのコンテナの中を、役割ごとのまとまり(API、ライブラリ)に分けて描く。
  4. レベル4 コード: クラスや関数の単位。ソースコード自体が最も正確なので、この文書では描かず、各箱にファイルの場所を書いている。
人 このシステム コンテナ(動く部品・DB) コンポーネント 外部のサービス

矢印は「矢印の元が、先を呼ぶ・使う」向きです。矢印の文字は、何をするかと使う技術です。

2. レベル1: システムコンテキスト図

PDF Exchange English は、PDF やテキストから英文を取り出し、日本語訳つきの学習カードとシャドーイング用テキストにする Web アプリです。Google でログインすると、結果が自動で保存されます。ログインしなくても、抽出・翻訳・音声再生は使えます(音声再生は現在、許可リストのアカウントだけ)。

登場するもの役割
利用者英語学習者。未ログインでも使える。ログインすると履歴が残る。
オーナー許可リスト(環境変数 FEATURE_ALLOWED_EMAILS)に入っているアカウント。音声再生を使える。利用制限は別枠で数える。
Claude API(Anthropic)英文を日本語に翻訳する。費用がかかるので、利用制限をかけている。
ElevenLabs英文を音声にする。費用がかかるので、現状はオーナーだけが使える。
Googleログイン(OAuth)。パスワードは、このアプリでは持たない。
Neon履歴・使用量・ログイン情報を保存する、マネージドの PostgreSQL。
Oxford Learner's Dictionaries英単語をクリックすると、別タブで開く辞書サイト。アプリのサーバーからは呼ばない。

3. レベル2: コンテナ図

システムの中は、大きく 3 つの部品と、手元で使う 1 つのスクリプトに分かれます。

通信内容
ブラウザ → サーバーHTTPS で JSON をやり取りする。呼ぶ先は /api/extract(ファイルから文章を取り出す)、/api/process(分割・翻訳)、/api/documents(履歴の保存・削除)、/api/tts(音声)、/api/usage(残りの使用量)、/api/auth/*(ログイン)。
サーバー → Claude / ElevenLabsAPI キーはサーバーだけが持つ。ブラウザには渡さない。
サーバー → Neon権限を絞った app_user ロールで接続する。行レベルセキュリティ(RLS)で、他人の履歴は読めない。
マイグレーション → Neon所有者ロールで、表の作成などを手元から実行する。所有者の接続文字列は Vercel に置かない。

4. レベル3: コンポーネント図(サーバー側)

Next.js サーバーの中を、入口(ルート)と部品(lib)に分けた図です。左が外から呼ばれる入口で、真ん中がそこから使われる部品、右が外のサービスです。

補足: 使用量の制限は、「誰の使用量か」を usage 部品が判定します。その判定で、利用者の種別(オーナーか、他の利用者か、未ログインか)を access 部品に問い合わせます。

6. 主な処理の流れ(翻訳から保存まで)

  1. 文章を取り出す: ブラウザが PDF やテキストを /api/extract に送る。PDF は pdf-parse で読み、文字が取れなければ tesseract.js で OCR する。貼り付けた文章は、このステップを通らない。
  2. 分割する: /api/process に action: "split" で本文を送ると、整形したうえで、約 1,500 文字ごとのかたまり(チャンク)に分けて返す。Claude も DB も使わない。
  3. チャンクごとに翻訳する: ブラウザが、チャンクを 1 つずつ action: "translate" で送る。サーバーは次の順に動く。
    1. 長すぎるチャンクは 413 で断る(上限を超えて枠を回避されないため)。
    2. 使用量を先に予約する(reserveUsage)。上限を超える場合や混み合っている場合は、429 で断る。
    3. Claude を Tool Use で呼び、文ごとの原文と日本語訳を受け取る。
    4. Claude の呼び出しが失敗したら、予約を返す(refundUsage)。
    チャンクごとに結果が返るので、長い文章でも進み具合を画面に出せる。
  4. 保存する: ログイン済みなら、結果を /api/documents に送って、documents と sentences に保存する。未ログインなら保存しない。
  5. 音声を作る(オーナーのみ): 学習カードのボタンから /api/tts を呼ぶ。サーバーは ElevenLabs で音声を作り、data:audio/mpeg;base64,... の形で返す。再生した音声は、そのカードの画面の状態にだけ残る(再読み込みすると作り直しになる)。

7. データ(DB)の構成

テーブル内容メモ
users / sessions / accounts / verificationsログインの情報(Better Auth が使う)db/migrations/0001_auth.sql
documents1 回の処理 = 1 件。タイトル、入力の種類(pdf / txt / paste)、元の文章、作成日時user_id で users につながる。本人の行だけ読める(RLS)
sentences1 文 = 1 行。位置、原文、日本語訳documents に紐づく。文書を消すと一緒に消える。本人の行だけ読める(RLS)
usage1 日ごとの使用量(翻訳した文字数)主キーは (subject_key, day, kind)。日付は UTC。

usage.subject_key は、「誰の使用量か」を表す文字列です。

  • u:<ユーザーID>: ログイン済みの個人(オーナーも同じ形)
  • ip:<ハッシュ>: 未ログインのクライアントごと(生の IP は保存しない)
  • anon:*: 未ログイン全体の合計
  • others:*: オーナー以外の全員(未ログイン + ログイン済み)の合計。費用の天井

9. 設計上の判断

  • 予約してから外部 API を呼ぶ: 翻訳の費用は、呼んだあとでは取り返せません。そのため、先に使用量を予約し、失敗したら返します。複数のリクエストが同時に来ても、枠を超えないよう DB 側で原子的に処理します。
  • サーバーレスなので、状態は DB に置く: 関数はリクエストごとに別のインスタンスで動くことがあり、メモリで使用量を数えられません。
  • アプリは、権限を絞った app_user で DB に接続する: 所有者ロールの接続文字列は、アプリの実行環境に置きません。万一アプリに脆弱性があっても、表の削除などはできません。
  • RLS で、履歴を本人だけが読めるようにする: アプリのコードに加えて、DB 側でも守ります。
  • IP アドレスは、鍵つきのハッシュにして保存する: DB が漏れても、元の IP を復元できないようにします。
  • 日付は UTC で保存し、画面ではタイムゾーンを明示する: 使用量の 1 日は UTC の日付で区切るので、日本時間の 9:00 にリセットされます。
  • 音声は、現状オーナーだけ: ElevenLabs の費用を抑える試験導入です。生成した音声は保存しておらず、再生のたびに再生成されます(改善案は Issue #44)。
