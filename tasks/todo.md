# 利用制限(翻訳の回数制限)と音声系機能の限定公開

## 背景
公開運用のため、無認証で外部の有料API(Claude / ElevenLabs)を叩ける状態を解消する。
`/api/process`・`/api/tts`・`/api/extract` にはセッション確認がなく、`translate` は `chunk` の長さ上限もない。

## 決定事項(2026-10-11 時点でユーザーと合意)
- 制限の単位は**文字数**(Claude・ElevenLabs とも入力テキストの長さに比例して課金されるため)
- チェックは**各APIルート内で、外部APIを呼ぶ直前**に行う(クライアント経由のチェックは回避できる)
- 使用量は Neon の `usage` テーブルで管理し、**1文のSQLで原子的に予約**する(同時リクエストの抜け道を作らない)。失敗時は返却する
- 未認証: **翻訳のみ**。IPごとの小さな枠 + 匿名全体の日次上限の2層(IPごとの枠 ≪ 全体の上限)
- ログイン済み: ユーザーごとの枠 + ログイン済み全体の安全装置(Googleアカウントの量産対策)
- **再生ボタン(TTS)・録音・文字起こしは、試験導入として許可リスト(自分のアカウント)のみ有効**
  - サーバー側(`/api/tts`, `/api/stt`)でセッションの email を許可リストと照合する。UIで隠すだけにはしない
  - 公開時は判定条件を変えるだけにする(ブランチ操作は不要)
- IP はサーバーから見えるグローバルIP。保存時はハッシュ化し、IPv6 は /64 でまとめる
  - Vercel の `x-forwarded-for` はクライアントの公開IPで、外部から付けられた値は上書きされる(公式ドキュメントで確認済み)。`x-vercel-forwarded-for`(同じ値で、手前にプロキシを置いても上書きされない)を先に見る
- **予算**: 自分以外のユーザー全員の利用総額を**月5,000円**に収める。自分(許可リストのアカウント)の利用は予算に含めず、別枠の安全装置だけを置く
  - 費用は Claude Haiku 4.5(入力$1 / 出力$5 per 100万トークン)で、1,000文字あたり約0.55〜1.1円(概算・実測前)。高いほうで計算し、31日で割って**自分以外の全員の合計 14万文字/日**
- 上限(1日・文字数、環境変数で上書き可。未設定や不正な値のときは既定値):

| 環境変数 | 既定値 | 意味 |
|---|---|---|
| `USAGE_LIMIT_ANON_IP_CHARS` | 12000 | 未ログイン・IPごと |
| `USAGE_LIMIT_ANON_TOTAL_CHARS` | 48000 | 未ログイン全体 |
| `USAGE_LIMIT_USER_CHARS` | 30000 | ログイン済み(自分以外)・ユーザーごと |
| `USAGE_LIMIT_OTHERS_TOTAL_CHARS` | 140000 | 自分以外の全員の合計(予算の天井) |
| `USAGE_LIMIT_OWNER_CHARS` | 100000 | 自分(安全装置) |
| `MAX_TRANSLATE_CHUNK_CHARS` | 2000 | 翻訳1リクエストの最大文字数 |
| `FEATURE_ALLOWED_EMAILS` | (空) | 音声・文字起こしと、予算の対象外(owner)になるメールアドレス(カンマ区切り)。未設定なら誰にも許可しない |

  - 環境変数は設定値の保管用。使用量(状態)は Neon の `usage` に置く(インスタンス間でメモリを共有しないため)
  - 変更は Vercel で保存したあと **Redeploy** が必要
- 保険として、Anthropic Console 側で月の利用上限を設定する(コードの制限が破られた場合に請求を止める)
- 日付は UTC で保存し、画面ではタイムゾーン(JST)を明示する(日付・時刻の規約に従う)

- [x] 2. 枠の数値を決めてユーザーに確認する(月5,000円の予算から逆算して合意)
- [x] 3. マイグレーション `db/migrations/0004_usage.sql` を作成(2026-10-11)。**本番へ適用済み(2026-10-11)**
  - `usage(subject_key, day, kind, amount, updated_at)`、主キーは前3列。`app_user` には select/insert/update のみ付与(delete は付与しない)
  - RLS は有効にしない(未認証の主体を扱うため user_id による行制限が成り立たない。理由はSQL内コメントに記載)
  - 検証: 本番DBでトランザクション内ドライラン→ロールバック(何も残らないことも確認済み)
  - **発見した欠陥**: `INSERT ... VALUES ... ON CONFLICT DO UPDATE ... WHERE` だと、WHERE は更新側にしか効かず、**新規キーの1回目は上限超過でも通る**(21,000 が上限 20,000 を素通り)。手順4では `INSERT ... SELECT ... WHERE $n <= $limit ON CONFLICT ...` にして、INSERT側にも条件を効かせる(ドライランで、新規超過=拒否、上限ちょうど=許可、直後の+1=拒否、拒否後に累計が変わらないことを確認済み)
  - **適用方法**: `scripts/migrate.mjs` は全ファイルを毎回実行し冪等でないため使わず、所有者ロールで0004だけをトランザクション内で適用した(`usage` が既に存在する場合は何もしない確認つき)。適用後、列・主キー・`app_user` の権限(select/insert/update可、delete不可)、行数0を確認
  - `app_user` 接続での実地確認: 予約SQLが通る(5,000)、上限超過は拒否、`delete` は `permission denied`、ロールバック後の行数0
  - `migrate.mjs` を冪等にする/対象ファイルを指定できるようにする改善は、今回のスコープ外(必要になった時点で別途対応)
- [x] 4. `src/lib/usage.ts` / `usage-limits.ts` / `client-ip.ts` を実装(2026-10-13)
  - 予約(`reserveUsage`)は、個人の枠と全体の枠を**同一トランザクション**で確認し、1つでも超えたら全体をロールバックする。デッドロック回避のためキー順に処理する
  - SQL は `INSERT ... SELECT ... WHERE` 形式(新規キーの1回目が上限を素通りする欠陥の修正)
  - 返却(`refundUsage`)は予約した日(UTC)の行から減らす。0未満にならず、失敗しても元の処理を邪魔しない
  - 主体: `owner`(許可リスト。予算に数えない)/ `user`(自分以外のログイン済み)/ `anon`(未ログイン)
  - 検証: 純粋関数(IP正規化・許可リスト・上限の読み取り)のアサーション、本番DBでソース内のSQLをドライラン(予約・途中失敗での巻き戻し・返却・別の日は不変)
  - **未検証**: 同時リクエストでの原子性(手順9でテスト用DBに対して実測する)
- [x] 5. `src/lib/access.ts`: 許可リスト判定(`FEATURE_ALLOWED_EMAILS`。メール未確認のアカウントは許可しない)
- [x] 6. `/api/process` の `translate` に、`chunk` 長の上限と文字数の予約を組み込み(2026-10-14)
  - 流れ: `chunk` 長の確認(超過は413)→ セッション取得 → 予約(超過は429)→ Claude → 失敗時は返却
  - 429 の応答: `error`(日本語の案内。リセットは「毎日 9:00(JST)」と明示)、`reason`(`personal` / `pool`)、`resetAt`(ISO 8601, UTC)、`Retry-After` ヘッダー
  - 旧経路(`action` なし)と、使われなくなった `splitAndTranslate` を削除(不明な `action` は400)。READMEの環境変数表と「既知の制限」を更新
  - Claude の `usage`(入力・出力トークン数)を `claude_usage` としてログ出力(本文は出さない)。実測の単価で上限を見直すため
  - 検証(ローカルサーバー + 本番DB、テスト用の行は削除済み): 長すぎる chunk=413 / 旧経路・不明action=400 / 個人の枠超過=429(`personal`、未ログイン向けの案内)/ 全体の枠超過=429(`pool`)/ 429で消費されない / **Claude失敗時は予約が返却され0に戻る**
  - **未検証**: 翻訳が成功する経路と `claude_usage` ログ。ローカルの `ANTHROPIC_API_KEY` が無効(`invalid x-api-key`)だったため。有効なキーで再確認が必要
  - **手順8への申し送り(重要)**: `page.tsx` は、チャンクの失敗を「スキップして続行」する。429 でも続行するため、(1)残りの全チャンクで無駄にAPIを叩く、(2)ログイン済みだと**途中までの翻訳が「完了」として保存される**。429 を受けたらループを中断し、案内を表示し、部分結果を保存しない(または保存前に確認する)こと
